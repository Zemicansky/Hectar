## 🚨 Быстрый поиск: "Что сломалось → какой файл нести"

| Симптом / что не работает | Файл, который несёте в чат |
|---|---|
| Не открывается погода, неверный прогноз, город не находится | `weather.js` |
| Карта не грузится, не переключаются слои (спутник/OSM/Sentinel) | `map.js` |
| Не рисуется поле тапами, площадь считается неверно, ошибка "поле пересекает само себя" | `map.js` |
| Лес/нерабочая зона не обводится или не вычитается из площади | `map.js` |
| Список полей, карточка поля не открывается, фото не грузятся | `fields.js` |
| История посева/уборки/полива в карточке поля не сохраняется | `fields.js` |
| NDVI не считается, неверные цвета на карте, график не строится | `ndvi.js` |
| Прогноз урожайности показывает неверные числа | `ndvi.js` |
| Заметки не сохраняются / не фильтруются | `notes-seasons.js` |
| Сезоны (создание, сравнение, тренды) не работают | `notes-seasons.js` |
| Не входит через Google / Email, не выходит из аккаунта | `firebase-sync.js` |
| Данные не синхронизируются между устройствами | `firebase-sync.js` |
| Удаление аккаунта не работает | `firebase-sync.js` |
| 3D-трактор не показывается, GPS не отслеживает, орудие не переключается | `tractor-3d.js` |
| Экспорт в Excel/PDF не работает, не экспортируется/импортируется GeoJSON | `export.js` |
| Переводы (RU/EN) неверные, тема (тёмная/светлая) не переключается | `core.js` |
| Настройки не сохраняются, модальные окна (попапы) не закрываются | `core.js` |
| Тосты (всплывающие уведомления) не показываются | `core.js` |
| Приложение не устанавливается на телефон / не работает офлайн | `sw.js` |
| Вход через Google совсем не подключается (ключи Firebase) | `firebase-init.js` |
| Что-то не так с версткой/цветами/расположением элементов | `style.css` |
| Не хватает кнопки/поля/блока на экране | `index.html` |

**Если не уверены** — просто опишите проблему словами, и решайте по таблице, либо принесите 2 файла, если она на стыке (например, "не сохраняется погода избранного города" → может быть и `weather.js`, и `firebase-sync.js`).

## 📁 Полный список файлов проекта

### `index.html`
**Что это:** Каркас страницы — все экраны, кнопки, модальные окна, разметка интерфейса. Здесь же подключаются все JS и CSS файлы (через `<script>` и `<link>` теги).
**Когда лезть сюда:** нужно добавить новый экран/кнопку/поле ввода, изменить текст на кнопке, поменять порядок подключения файлов.
**Не лезть сюда, если:** проблема в логике (расчётах, сохранении данных) — она не здесь, а в соответствующем .js файле.

---

### `core.js` — фундамент приложения
**Что внутри:**
- Переводы интерфейса (RU/EN) — `t()`, `applyTranslations()`, `setLang()`
- Загрузка/сохранение настроек пользователя
- Тема оформления (тёмная/светлая), Safe Area для iPhone с "чёлкой"
- Модальные окна: открытие/закрытие (`openModal`, `closeModal`, `closeAllModals`)
- Всплывающие уведомления (`showToast`)
- Общие мелкие утилиты: генерация ID (`generateId`), форматирование площади (`formatArea`), защита от опасного HTML (`escapeHtml`)
- Список культур (пшеница, кукуруза и т.д.) и подписи к ним

**Важно:** этот файл используют ВСЕ остальные файлы (например, `weather.js` вызывает `formatArea()` из `core.js`). Поэтому в `index.html` он должен подключаться **первым**, до остальных.

**Когда лезть:** проблема с языком интерфейса, темой, всплывающими окнами, или ошибка "функция не определена" в любом другом файле (значит, скорее всего, не подключен `core.js`).

---

### `map.js` — карта и рисование полей
**Что внутри:**
- Инициализация карты (Leaflet), переключение слоёв: Спутник / Sentinel-2 / OSM
- Поиск мест на карте, история поиска
- Геолокация (кнопка "где я")
- Рисование поля тапами по точкам, отмена точки, проверка на самопересечение полигона
- Обводка леса/нерабочих зон и вычет их площади из общей площади поля
- Подписи на карте (названия полей)

**Зависит от:** `core.js` (утилиты), библиотеки Leaflet и turf.js (подключены отдельно, не в этом проекте)

**Когда лезть:** карта не грузится, не переключаются слои, не рисуется поле, площадь считается неправильно, ошибка при обводке леса.

---

### `fields.js` — поля и их карточки
**Что внутри:**
- Список всех полей пользователя, фильтры по культурам
- Открытие/закрытие карточки поля
- История полевых работ внутри карточки: посев, уборка, полив, опрыскивание, культивация, дискование (добавление/редактирование/удаление событий)
- Название, культура, цвет, площадь, периметр поля
- Загрузка фото поля (до 5 штук)
- Стадия вегетации культуры (расчёт по дате посева)

**Зависит от:** `core.js`, `map.js` (для получения площади/периметра нарисованного поля)

**Когда лезть:** список полей, карточка поля, история сезона, фото не работают как надо.

---

### `ndvi.js` — вегетационный индекс и урожайность
**Что внутри:**
- Получение данных NDVI со спутника (NASA GIBS MODIS)
- Расчёт NDVI по каждому полю, цветовая шкала и легенда
- График NDVI по месяцам
- Прогноз урожайности на основе NDVI и культуры (простой и детальный расчёт)
- Оценка состояния посевов (здоровое / нужно внимание / плохое)

**Зависит от:** `core.js`, `map.js` (координаты поля для запроса спутниковых данных)

**Когда лезть:** NDVI не считается, неверные цвета на карте, график не строится, прогноз урожайности выглядит странно.

---

### `weather.js` — погода
**Что внутри:**
- Погода по конкретному полю или по выбранному городу (сервис Open-Meteo)
- Поиск города, избранные города (до 5 штук)
- Текущая погода + прогноз на несколько дней
- Рекомендация "можно/нельзя опрыскивать" на основе погоды

**Зависит от:** `core.js`, `fields.js` (список полей для выбора)

**Когда лезть:** погода не грузится, город не находится, избранные города не сохраняются, рекомендация по опрыскиванию неверная.

---

### `notes-seasons.js` — заметки и сезоны
**Что внутри:**
- Заметки, привязанные к полям, с фильтрами по типу работ
- Управление сезонами (создание "Сезон 2026", переключение активного сезона)
- Сравнение сезонов между собой (урожайность, осадки, качество)
- График трендов по сезонам

**Зависит от:** `core.js`, `fields.js`

**Когда лезть:** заметки не сохраняются/не фильтруются, сезоны не создаются/не сравниваются.

---

### `firebase-sync.js` — аккаунт и облако
**Что внутри:**
- Вход: Google, Email/Пароль, режим гостя
- Регистрация, восстановление пароля, выход, удаление аккаунта
- Профиль пользователя
- Синхронизация данных в облако и обратно: поля, заметки, сезоны, настройки, избранные города
- Обработка ошибок синхронизации (например, если пропал интернет)

**Зависит от:** `firebase-init.js` (настройки подключения к Firebase), `core.js`, а также ото всех файлов с данными (`fields.js`, `weather.js`, `notes-seasons.js`) — потому что синхронизирует их данные.

**Когда лезть:** проблемы со входом/выходом, синхронизацией между устройствами, удалением аккаунта.

---

### `firebase-init.js` — подключение к Firebase (уже отдельный файл)
**Что внутри:** Импорт функций Firebase SDK (Auth + Firestore) и передача их в `window._fbModular`, чтобы обычные скрипты могли ими пользоваться.
**Когда лезть:** нужно вставить свой `firebaseConfig` (ключи проекта Firebase), либо обновить версию Firebase SDK.
**Обычно трогать не нужно** — это техническая "прослойка", которая редко ломается сама по себе.

---

### `tractor-3d.js` — 3D-трактор и GPS-трекинг
**Что внутри:**
- 3D-сцена (Three.js): модель трактора, земля, орудия (опрыскиватель, культиватор и т.д.)
- Отслеживание позиции трактора по GPS в реальном времени
- Физика движения, симуляция вождения, ручное управление (для теста без реального трактора)
- Отрисовка покрытой площади (какие участки поля трактор уже проехал)
- Полосы вождения (guidance lightbar), радар, итоговая сводка после заезда

**Зависит от:** `core.js`, `map.js`/`fields.js` (границы поля для отображения)

**Самый изолированный блок проекта** — почти не пересекается по смыслу с остальными файлами, поэтому безопаснее всего редактировать отдельно.

**Когда лезть:** 3D-трактор не отображается, GPS не работает, орудие не переключается, физика ведёт себя странно.

---

### `export.js` — экспорт и импорт данных
**Что внутри:**
- Экспорт списка полей в Excel
- Экспорт в PDF (отчёт)
- Экспорт полей в формат GeoJSON (для других ГИС-программ)
- Импорт полей из GeoJSON

**Зависит от:** `core.js`, `fields.js`

**Когда лезть:** экспорт/импорт не работает, файл скачивается пустым или повреждённым.

---

### `style.css`
**Что внутри:** Все стили приложения — оформление карты, полей, погоды, модальных окон, 3D-трактора, темы (тёмная/светлая), адаптация под мобильные экраны. **Не разбит на части** (сознательно — см. объяснение ниже).
**Когда лезть:** что-то выглядит не так, неправильные цвета/отступы/размеры.

---

### `sw.js` — Service Worker (офлайн-режим)
**Что внутри:** Логика кеширования, чтобы приложение работало без интернета и устанавливалось на домашний экран телефона (особенно важно для iPhone).
**Когда лезть:** приложение не работает офлайн, не обновляется до новой версии после правок (тогда нужно вручную поднять номер `CACHE_NAME` внутри файла).

## 🧭 Порядок подключения файлов в index.html

Важно, что JS-файлы подключаются в определённом порядке — потому что более поздние файлы используют функции из более ранних:

```
1. firebase-init.js   (настройка Firebase)
2. core.js             (утилиты — нужны всем)
3. map.js               (карта — нужна полям и NDVI)
4. fields.js            (поля — нужны погоде, заметкам, экспорту)
5. ndvi.js
6. weather.js
7. notes-seasons.js
8. firebase-sync.js    (синхронизирует данные всех предыдущих)
9. tractor-3d.js
10. export.js
```

Если в будущем добавляете новый файл — спросите ИИ, от каких файлов он зависит, и вставьте его в цепочку в правильном месте.

## ✅ Правила безопасного вайб-кодинга с этой структурой

1. **Одна проблема — один (максимум два) файла в чат.** Не вставляйте весь проект, если чините погоду.
2. **После каждой правки — проверяйте в браузере**, прежде чем просить следующую правку.
3. **Делайте бэкап** (копию папки или commit в git) перед крупными изменениями.
4. **Если ИИ говорит "нужно поменять ещё вот в этом файле"** — это нормально для связанных фич (например, новое поле данных → `fields.js` + `firebase-sync.js`). Просто приносите оба файла и явно указывайте, что они связаны.
5. **Не просите "перепиши всё с нуля"** — просите точечные изменения в конкретном файле, так безопаснее.
